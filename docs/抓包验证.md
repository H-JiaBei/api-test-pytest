# Fiddler / Charles 抓包验证说明

目的：抓取真实请求与响应，验证接口实际行为与预期一致，并作为项目佐证截图。

## 一、工具选择

- **Fiddler Classic**（Windows，免费）—— 推荐本机使用。
- **Charles**（跨平台，试用版每 30 分钟重启一次）。

默认代理端口均为 **8888**。

## 二、Fiddler 配置 HTTPS 解密（最容易踩坑的一步）

1. 打开 Fiddler → 菜单 `Tools` → `Options` → `HTTPS` 标签。
2. 勾选 `Capture HTTPS CONNECTs` 和 `Decrypt HTTPS traffic`。
3. 首次会提示安装根证书 → 点 `Yes`，按提示安装并**信任**证书。
4. `...from all processes` 或只解密浏览器/客户端，选第一项即可。
5. 重启 Fiddler 生效。

> 抓不到 https 包，99% 是因为根证书没被系统信任。可在「证书管理器 → 受信任的根证书颁发机构」里确认有没有 `DO_NOT_TRUST_FiddlerRoot`。

## 三、只看目标接口（过滤）

在 Fiddler 左下角 `QuickExec` 或过滤框输入：

```
@host=jsonplaceholder.typicode.com; @host=httpbin.org
```

这样只显示被测域名的流量，排除其它干扰。

## 四、抓取两类请求

### 1. 抓 Postman 发出的请求
直接在 Postman 里点 Send，Fiddler 会自动抓到（Postman 默认走系统代理）。

### 2. 抓 Python（requests）发出的请求
Python 的 requests **默认不走系统代理**，需要手动指定。取消 `conftest.py` 里两行注释：

```python
session.proxies = {"http": "http://127.0.0.1:8888", "https": "http://127.0.0.1:8888"}
session.verify = False
```

再运行 `pytest`，Fiddler 即可抓到 Python 发出的请求。

## 五、抓到一个请求后要看什么

| 关注点 | 位置 | 预期结果示例 |
|---|---|---|
| 请求行 | Inspectors → Headers | `GET https://jsonplaceholder.typicode.com/posts/1 HTTP/1.1` |
| 请求方法 | Headers | GET / POST |
| Content-Type | Headers（POST） | `application/json` |
| 请求体 | Inspectors → WebForms/JSON | `{"title":"foo",...}` |
| 响应状态码 | Headers 第一行 | `200 OK` / `404 Not Found` / `201 Created` |
| 响应体 | Inspectors → JSON | 字段 `id/userId/title/body` |

## 六、验证结论模板（可直接写进 README/报告）

> 通过 Fiddler 抓包可见：`GET /posts/1` 返回 `200`，响应体含 `id=1`、`title` 为字符串、`userId` 为整型，与实际断言一致；`GET /posts/0` 返回 `404`，与边界用例预期一致。接口行为符合预期。
